# Show HN draft

**Title:** ForgeFix – one command to set up, health-check, and repair any open-source repo (MIT)

**Body:**

I kept hitting the same first hour in every new repo: guess the install command, find no
lockfile, hunt for the test runner, wonder if it's maintained. So I built ForgeFix, a CLI
that turns that tribal knowledge into a deterministic check:

- `forgefix doctor` — scans for README, one-command install line, lockfile, pinned deps,
  Dockerfile/devcontainer, CI, SECURITY.md, LICENSE, and a working dev environment.
  Prints pass/warn/fail with fix suggestions and a 0–100 score. `--json` and
  `--min-score` for CI gates.
- `forgefix up` — dry-run by default. With `--apply` it repairs *missing* setup files
  (never overwrites, never invents a LICENSE), creates the venv, installs deps, writes a
  lockfile, runs the tests. On the bundled broken fixture: 42/100 -> 91/100, tests pass.
- `forgefix report` / `forgefix serve` — markdown report and a FastAPI endpoint exposing
  the same checks.

Notes on the boring-but-important parts:

- Original code, MIT. It only reads repo *metadata* (file names, README text) — it never
  copies code from the repos it inspects, and it makes no network calls during scans.
- No `shell=True`, no `eval`; sanitized argv + bounded timeouts; bandit, gitleaks,
  CodeQL in CI; 104 tests, 96% coverage, score math pinned by unit tests.
- Plugin system via the `forgefix.plugins` entry-point group; broken plugins are logged
  and skipped, never crash a scan.
- Scans are read-only; `up` is dry-run until you say `--apply`.

Limitations, honestly: bring-up detects python/node/go only (rust/java on the roadmap);
the hosted dashboard in `docs/monetization.md` is a plan, not a product — the CLI is the
whole product today. Demo GIF is generated by a scripted vhs tape, so the recording shows
a real session.
